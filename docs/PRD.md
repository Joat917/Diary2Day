# Diary2Day 需求文档 v0.3

输入依据：SwashbucklerDiary（侠客日记）源码走查。技术栈已定 Tauri v2 + Vue 3 + TS，桌面和移动同期。

这一版把重心从安全挪回界面组织。核心判断：**日记 App 的成败在"记一条要几步"和"三个月后能不能找到它"，其余都是配菜。**

---

## 1. 三条取向

1. **数据可达优先。** 任何时候都要能把全部内容变成人眼可读、别的软件能打开的文件带走。应用不锁格式、不锁目录、不搞只有自己能读的容器。
2. **写入摩擦最小。** 从"想记"到"开始打字"，移动不超过 2 步，桌面不超过 1 步。任何增加这一步数的设计都要给出对等收益。
3. **读和写是同一个东西。** 不区分"阅读页"和"编辑页"。这一条能砍掉参考项目里最大的一块重复实现。

---

## 2. 界面组织

### 2.1 导航总图

**移动（3 个底部入口，不是 4 个）**

```
今天(首页)  ·  发现(搜索/筛选)  ·  我的
```

参考项目是 日记/日历/文件/我的 四个 tab。合并前两个（见 2.2），去掉"文件"这个独立 tab（见 2.4）。第三个入口叫"发现"而不是"搜索"，因为它无查询词时是浏览和筛选的入口，不是空框。

**桌面（三栏，无底部导航）**

```
┌ 迷你月历 ┬ 当日/结果列表 ┬ 详情（即编辑） ┐
│  打点    │   卡片流      │   常驻         │
└─────────┴──────────────┴───────────────┘
```

左栏可折叠成图标条。详情栏常驻是桌面体验的关键：参考项目在桌面也是"点卡片跳走 → 编辑 → 返回列表"，来回丢失滚动位置和上下文，这是它桌面端最大的割裂感来源。

### 2.2 首页 = 日历 + 时间线，一个视图两种密度

不分开做 Home 和 History 两页。它们的差别只是时间粒度和列表密度，分成两页会产生两套列表逻辑、两个筛选状态、两份跳转关系。

**移动：**
- 顶部是一条**可横向滑动的周条**（7 格，显示星期 + 几号 + 打点）。周条是首页唯一常驻的时间导航。
- 周条下方是**"今天"卡片**：一块在日记今天常驻的轻量输入区，点一下就能写，写完点保存/失焦即落库，不跳页；选中历史或未来日期时它让位给列表。这是全 App 最重要的一块 UI，见 §3 的步数目标。
- 再往下是**当日条目**（一天可以有多条，按时间倒序叠放）。
- 周条**下拉/点日历图标**展开成整月视图（月历 + 打点 + 月份切换）。整月是"翻旧账"时用的一次性浮层，不是常驻页面。
- 参考项目"日历滚出视口后标题变成日期入口"那个交互（`IntersectElement` + `DatePickerDialog`）确实好用，但那是"日历页 + 列表页拼在一起"的补救。改成常驻周条之后这个状态机不需要存在了——这是简化带来的收益，不是砍功能。

**桌面：** 左栏迷你月历常驻（打点 + 月份切换），点某天出中间列表，等价于移动的周条但不用展开。

**要求（行为层面，不谈实现）：**
- 打点日期不能因为数据变多而变卡。参考项目是把全部日记读进内存再过滤，10 万条时首页会先卡一下——这条要在早期就用真数据压一次。
- 周条与月历上任何日期都能选中查看，但写入只发生在**当前日记日**：历史与未来日期只读，不提供新建或编辑入口（§2.3、§2.8）。
- 时区：一条日记落在哪一天，按**记录时的那天**算，跨时区旅行不能把周日的日记甩到周一。参考项目直接拿 `CreateTime` 转换，没考虑这个。
- 修仙模式（§2.8）：每日分界点可设为 00:00–07:59 之间的任意分钟（默认 00:00，即不分界）。分界点之前的记录归入前一天，显示为 24 点之后的时刻（如 01:00 显示为 25:00）；"今天"按日记日算，而不是自然日。切换分界点后历史记录按新分界点重新归属。

### 2.3 详情即编辑（同一个页面）

点开一条日记 = 进入一个既可读又可写的区域。

- 打开当前日记日的一条记录，默认直接进可写态（窄屏与宽屏一致）；设置里的「打开即进入编辑」关掉后，打开先落预览，再由"编辑"FAB / 顶栏铅笔 / 双击正文 / `E` 键进编辑。显式的编辑意图——新建入口与新建后跳转带的 `?edit=1`——不受该开关影响。从搜索结果进入时始终先只读并定位命中，再由这些入口进编辑。编辑态下点击正文以外区域（编辑器失焦）即回到预览，再由这些入口继续写；未落库的草稿不因失焦退出编辑。初版设想的"窄屏先读、宽屏先写"被取消：既然写入只发生在当前日记日（§2.8），一次打开多半就是继续写；而只读渲染与编辑器排版对不齐（marker 占位、`pre` 边框、行高都不同），就地换渲染器必然有一次可见重排，把它放进进入页面的动画里，比放在用户第一次点击时更好。"两个态一套 UI"仍然成立——一套元信息、一套滚动位置、一套保存状态机，换掉的只有渲染器。
- 元信息（心情、天气、标签、日期）在只读态是行内的小 chip，编辑态变成可点选的控件。不做参考项目那种"OtherInfo 一行三个按钮 + 日期时间星期字数"的常驻元信息行——默认只显示**有值的**字段，全空时只显示日期。新建页也可以先选元信息，但它只暂存在内存，随正文在第一次保存时一起写入；正文仍为空就离开，元信息一并丢弃，不留空条目。
- 标题：默认**不做独立标题字段**。标题就是第一行（参考项目 `DiaryCardDefaultTitle` 也是这么派生的，既然能派生就别让用户多填一个框）。想分开的话留一个开关，但默认关。
- Markdown 语法渲染/源码两个态：默认所见即所得（Vditor IR 那种），提供一个"看源码"切换。日记场景下用户不该被迫理解 markdown。唯一例外是首页今天卡片——它是一块纯文本输入区，所见即所得集中在详情里，理由是快速记一条用不到工具栏，而常驻输入区要求点开即用（§3 的 0 跳页目标优先于这一屏的排版能力）。
- **保存**：失焦、切条目、切后台时冲刷；输入停顿去抖 ~1s 落一次（首页今天卡片例外，见 §2.8）。参考项目是"每 5 秒定时轮询存一次"，且"正文清空即删除这条日记"——后者要命，改成：正文清空只提示，删除必须是显式动作。空白草稿不落库，新建后什么都没写就离开不会留下空条目。
- **只读过去**：日记日早于当前日记日的条目只能预览，不提供编辑入口、不触发自动保存、双击与 `E` 无效，离开不写库；置顶与删除仍可用。未来日期同样只读，新建与编辑仅发生在当前日记日（§2.8）。
- **预览导出图片**：预览态顶栏多一个「导出为图片」，把当前正文按当前主题渲染成一张 PNG（固定 640px 宽，整篇一张长图）。历史与未来日期的只读条目也能导出——它只读当前正文，不写库。正文里的音视频截不出来：音频画成起点的进度条加总时长，视频取一帧作封面并标总时长，嵌入内容仍是一行说明；时长或封面读不到（编码不支持等）时退回一行类型说明，不阻断导出。不显示随机附件文件名——它对读者没有信息量。单张高度超过 16384px 直接报错，不截断、不降质。这是分享用的临时产物，不算数据导出通道（§5 的人可读导出不受影响）。

### 2.4 附件：不做媒体库

参考项目有底部"文件"tab（图片瀑布流 / 音频卡 / 视频）、引用计数、"查看该文件被哪些日记引用"、"清理未使用文件"。这一整套对个人小项目**不划算**：它把 F-5/F-6 那类索引漂移问题（正文里正则扫路径反推关联、修复靠手点工具）整个引进了项目。

改成：
- 图片插入后就存在日记里，阅读器点开看大图（缩放/双击复位）；
- 日历列表卡片上显示图片/音频/视频数量的小角标，够用了；
- 附件统一放在数据目录下的 `assets/` 子目录，**文件名随机**（不要用内容 hash 当文件名——参考项目用 SHA256 命名，等于把"两张图内容相同"这个信息泄露在文件名里，还妨碍备份）；
- 附件是否还在用只看当前文档：离开编辑时清理本次会话中最终正文不再引用的文件（后台执行，不阻塞切页）；正文仍引用的一律保留。导出照常带上全部 assets。
- 不维护引用计数，但给一个**手动**逃生口：「我的 → 数据 → 清理未使用附件」按下后扫描全部正文，删除没有被任何条目引用的附件（回收站条目的引用也算）。不自动运行，也不提供"某文件被哪些日记引用"的浏览界面。彻底删除与清空回收站时顺带清理失去引用的附件。

真到了附件多到需要整理的程度，再加一个只读的画廊视图（挂在"我的"页里，不占底部入口）。

### 2.5 搜索与筛选

**一个输入框，不跳页。** 参考项目从首页图标跳到 `/search?query=` 独立页面，输入框还得再点一次才聚焦。改成：

- 移动：首页顶部常驻搜索框（点击即聚焦），输入即把首页列表切换成结果列表；"发现"tab 是无查询词时的筛选浏览入口。
- 桌面：中间列表顶部常驻输入框，实时过滤。

**行为要求：**
- 匹配标题（即首行）与正文，忽略大小写。
- **单个汉字的查询必须能出结果。** 别默认"关键词检索"——参考项目的 `LIKE '%x%'` 虽然慢，但它对中文友好。任何"分词/前缀索引"的做法都要保证短查询有兜底路径，绝不能出现"搜'梦'返回空"。
- 结果里命中片段高亮，点条目进入详情并**定位到第一处命中**（参考项目带 `?query=` 深链进阅读页自动开查找，这个体验值得原样保留）。
- 筛选维度 v1 只留**标签**一种：发现页搜索框下方一排标签 chip，与查询词同时生效。心情、时间范围不做常驻筛选条。
- 空结果页给出路（清除筛选 / 去新建），不要只写"没有结果"。

**高级搜索（暂不实现）**：心情多选（含"没有指定心情"）、起止日期、多关键词、正则表达式统一收进"高级搜索"。它不是核心或常用功能，当前不提供入口，也不预先摆在界面上；后端查询参数保留，等确有需要再一次性接入。

**不提供应用内快捷键**：没有文内查找条、没有 `Ctrl/⌘+F`、`Ctrl/⌘+Enter`、`E` 之类需要记忆的按键，移动端也不依赖快捷键。搜索跳转只做一次性的命中高亮与定位，不引入查找工具栏。

### 2.6 标签 / 心情 / 天气（元信息）

- **标签**：新建时查重（折叠大小写与全角），从详情页行内加，也可在编辑器里加。标签列表是"发现"tab 的一种呈现，不按标签做独立页面。插入面板与发现页的标签条只列出至少被一条存活日记引用的标签；零引用的残留标签不展示，键入同名时会直接复用。
- **心情**：固定图标集单选，17 项（见 §7）。
- **天气**：M3 加入，固定 17 图标单选（见 §7）。它们对"三个月后找回来"几乎没有帮助（没人按天气检索日记），所以只留图标、不留筛选，录入不强制。地点不单开字段，直接作为一个标签写（如 `#杭州`），不再另设地点选择器。
- **置顶 / 敏感标记 / 模板**：置顶留（一天多条时真有用）；模板先只做"复制上一篇内容新建"这一个动作，够用；"敏感/隐私标记"随 §5 的应用锁一起做，成本极低。

### 2.7 我的 / 设置：一个页面，不要子页面树

参考项目有 10 个左右设置子页（首页、日历、日记、大纲、卡片、提示、模板、应用锁、更新、权限、scheme）。个人项目没必要做二级页树，改成**单页分组滚动**，分组 = 数据 / 外观 / 日历 / 记录 / 应用锁 / 回收站 / 关于。数据组排在最上面：统计、目录与导出/备份/清理是用户打开设置最常看的。

需要的开关（其余全砍）：主题（独立页面：浅色/深色各四套卡片，点击即切；首次启动按系统明暗默认纸白或墨夜，之后不再跟随系统）、语言、日期时间显示格式、周起始日、卡片时间（开关：开 = 显示最后编辑时间，关 = 记录时间；只影响卡片显示，排序始终按记录时间，默认关）、每日分界点（修仙模式，00:00–07:59，按分钟可调，00:00 即关闭）、首行缩进、打开即进入编辑（开关：开 = 打开条目直接编辑，关 = 先落预览；默认开，新建入口不受影响）、关闭动画（应用内开关，不跟随系统）、图片懒加载、列表统计卡（仅宽屏显示）、应用锁、快速记录（冷启直达今天）、打开数据目录、导出全部、备份/恢复、清理未使用附件、关于与版本。每日分界点一改，历史条目、回收站与打点在同一事务内重新归属（§2.8），不需要用户手动修复。备份时可选择设置口令生成加密包（§5.5）。

砍掉的：更新提示与多渠道跳转、权限页（改成用到时系统弹窗）、成就、赞助页、商店评分、联系方式、备案号、链接卡片富化（走第三方代理，等于把你读的链接交给别人）、九宫格图案锁、双库隐私模式。

### 2.8 修仙模式：日界与写作边界

一句话：**"今天"是日记日，不是自然日。** 每天有一个可调的分界点（00:00–07:59，默认 00:00），分界点之前的凌晨算前一天。

- **公式**：`day_key = date((recorded_at → recorded_off 得到本地墙钟时间) - day_boundary_minutes)`。`recorded_at` 与 `recorded_off` 是记录时的事实，永不因为分界点变化而改写，所以分界点随时可以改回去。
- **显示**：落在分界点之前的时刻显示为 24 点之后。分界点 04:00 时，凌晨 01:30 的条目显示在昨天的日期下，时间写作 `25:30`；周条与月历的"今日"环也落在昨天。
- **重新归属**：切换分界点是一次全局重排——所有条目（含回收站）的 `day_key` 与 `day_mark` 在同一个事务里重算，月历打点、周条与列表按新归属显示。用户不需要、也不应该看到"修复"按钮。
- **写作边界**：只有当前日记日可以写。今天卡片只在选中的是日记今天时出现；选中历史或未来日期时，主操作从"新建"变成"今天"（定位图标 + 次级样式），点了只是切回今天，不写任何东西。没有"往这一天补一条"的入口。
- **保存的落点**：快速输入提交非空内容后清空输入区、刷新列表并停在今天。空白内容不提交，也不产生草稿；进入新建页什么都没写就离开，同样不会留下空条目。
- **只读过去**：早于日记今天的条目在详情里只有预览，没有编辑入口，也不会自动保存（§2.3）。未来日期同理。
- **空态文案**：列表为空时按选中日期与日记今天的关系显示三句之一——"这一天没有记录"（过去）、"今天还没有记录"（今天）、"这一天还没有到来"（未来）。文案由前端按日期比较得出，不查库。
- **动效语义**：翻日历、换周、换日列表都按时间轴定向——去更早的日期，新内容自左入、旧内容向右出；去更晚的日期反向。换月与换日 240ms、16/48px 位移，换周 180ms、16px（UI.md §5.1）。打开"关闭动画"后全部瞬时完成。

## 3. 四条关键路径（这条文档的重点）

| 路径 | 目标 | 设计是否达成 |
|---|---|---|
| **记一条（移动）** | 打开 App → 直接点今天卡片开始打字 = **0 跳页、2 步内** | 达成。默认冷启进今天 + 常驻输入卡片。若冷启后进的是"列表要再点新建"，就是失败设计 |
| **记一条（桌面）** | 常驻首页直接打字 = **1 步** | 达成。分享接收已在 Android 端接系统分享（文本/图片/音视频 → 新条目）；桌面分享入口与全局快捷键不做 |
| **找一条** | 一个输入框，输入即过滤，回车进详情并定位命中 = **1 次输入 + 1 次点击** | 达成。前提是短查询不返回空（§2.5） |
| **回看某天** | 滑周条 / 点迷你月历 = **1 步** | 达成。周条常驻，不需要展开整月 |
| **带走全部数据** | 导出 → 得到 markdown 目录 + assets 文件夹，任意编辑器可读 = **1 次操作** | 达成，见 §5。这是"可达优先"的落地点 |

所有"记一条"路径都只落在当前日记日（§2.8）；"回看某天"允许选未来日期，但那里只有只读。

一个提醒：`快速记录`、`今天卡片`、`全局快捷键`这三件事本质是同一个诉求（缩短记一条的路径），别都做，选一个主路径 + 一个补充。当前选择：常驻今天卡片为主，冷启直达编辑为可关开关；全局快捷键与需要记忆的应用内按键都不做。

## 4. 明确不做

云同步、多设备同步、协作、账号体系、服务端、WebDAV、局域网传输、生物识别、录音/摄像直采、地图定位、外部天气 API、媒体库与附件回收、成就系统、应用内更新弹窗、整库加密（见 §5）、隐藏卷/可否认加密。

**往历史或未来日期补写**：写入只发生在当前日记日（§2.8）。旧日记永远只读；要补记，就在今天的条目里写清事情发生的时间，而不是伪造一条过去的记录。

首启不要自动写入一批示例日记（参考项目选完语言就灌几篇本地化示例），那会污染搜索、统计和备份。要引导就做一次性、可一键清除、不计入统计的 demo 标记。

## 5. 数据可达（原"安全"章的替换）

原则：**默认不加密，且这不影响发布。**

理由是整库加密和可达性直接冲突：口令忘记 = 数据永久无法取回，且文件对外部工具完全不透明（明文 SQLite 至少还能用 DB Browser 手动捞）。对一个装个人日记的单机应用，**把自己锁死的风险高于别人拷走文件的风险**。而且桌面/移动的应用私有目录在多数部署上本来就有系统级加密（iOS 全量、Android 凭据加密区、Win/macOS 装了 BitLocker/FileVault 的机器），加密带来的增量比看起来小。

所以只做这几件事：

1. **不做整库加密。** 数据库文件明文存在应用数据目录，路径显示在"关于/数据"里，并有"打开数据目录"按钮（移动端不给，平台不允许）。
2. **导出是逃生通道，必须人可读。** 一键把全部内容导成一个目录：每条日记一个 `.md`（第一行或 front-matter 带时间/心情/标签），附件放 `assets/` 子目录，正文用相对路径引用附件。导出产物**不打包专有格式、不加口令、不用自定义 zip 结构**，用户拿到就能用其他软件打开。
   - 顺带要求：任何导出格式要么能对称导回，要么在按钮上写清"仅导出"。参考项目的 xlsx 导出会把天气/心情翻译成显示文本（丢原始码值）且没有对应导入，这种"看起来能备份其实回不来"是可达性最差的形态。
3. **备份/恢复（应用自己的格式，含附件）** 照做，但要清楚标注"这是给 Diary2Day 恢复用的，不适合拿来看"，避免用户误以为备份就是导出。
4. **应用锁 = UI 门，一天工期的东西。** 可选的 4 位数字口令或主口令，只挡"设备已解锁时旁人翻看"和离开自动重锁，明确告诉用户这不保护文件。不做隐私模式第二个库——参考项目那套（全局标志位决定每次查询用哪个库）在异步写入跨越模式切换时会写错库，是纯粹的复杂度来源。想做的话就一个"敏感"标记 + 默认在列表里折叠正文。
5. **备份包加密（可选口令）。** 备份时在对话框里填口令，生成 `.ddbak` 加密包；留空仍是普通 `zip`。口令不设长度下限——短口令只在对话框里提示"口令过短影响安全性"，不阻止生成；首尾不能有空格，两次输入一致。对话框可勾选"记住口令"：口令加密存到本机数据目录的 `backup-password.bin`（固定密钥写在程序里，只能防明文落盘；该文件不进入备份包），下次备份或恢复时自动填入；不勾选完成操作即删除记录。实现：口令经 Argon2id（m=32 MiB, t=3, p=1）派生 32 字节密钥，再用 XChaCha20-Poly1305 按 1 MiB 分块做认证加密；每帧带递增序号（防重排），最后一帧长度为 0（防截断）。恢复时先看文件头：加密包必须输入口令，解密完整后才进入替换管线，口令错误统一报"口令不正确，或备份已损坏"，现有数据不动；普通 zip 备份照旧直接恢复。**口令无法找回**——文件里没有可读内容，也不留后门。人可读的 Markdown 导出永远不加密（§5.2），加密只作用于备份包。
6. **删除一律软删除 + 回收站**（默认 30 天）。可达性一半靠加密，一半靠"误删还能捞回来"。软删除保留附件文件；彻底删除或清空回收站时，同步删除不再被任何剩余条目引用的附件文件。

## 6. 别照抄的坑（一句话版）

1. 搜索 `LIKE '%x%'` 全表扫——不用现在解决，但要用真数据（1 万条）压一次，心里有数再决定要不要上索引。
2. 日历页把全部日记读进内存再过滤——同上，早期用大数据测一次首页与打点。
3. 媒体关联靠正则扫正文派生，漂移了要用户自己点"修复工具"——所以 §2.4 干脆不做媒体库。
4. 附件用内容 hash 当文件名——泄露内容相同性，且妨碍后续任何变更。用随机名。
5. "正文为空即删除该条日记"——误删路径，不可接受。
6. 筛选 UI 摆出"全部满足"但后端返回永假——宁可不给选项。
7. 隐私标志放全局可变状态、每次查询现读来选库——异步竞态写错位置的根源。
8. 双份导航状态（列表页 + 详情页 + 编辑页三套菜单互相复制）——所以 §2.3 合并读写。
9. 声明了但从未读写的设置字段、枚举里没有定义的成就类型、`[Obsolete]` 却还留在表里的列——别留。
10. 密码哈希兼容老的 MD5 路径——新库从零开始，没有历史包袱可背。

## 7. 需要抄过来的清单

**心情图标（17）**：angry confused cool cry dead devil excited frown happy kiss lol neutral poop sad sick tongue wink（MDI 表情图标）。

**天气图标（17，M3）**：cloudy dust fog hail hazy hurricane lightning lightning-rainy pouring rainy sleet snow sunny sunny-off tornado ultraviolet windy。

**时间格式选项**：显示 `yyyy/MM/dd dddd` / `MM/dd HH:mm` / `yyyy年M月d日`；卡片 `MM/dd`；插入时间戳默认 `yyyy/MM/dd HH:mm:ss`。

**时段问候 5 档**：06–11 早上好、11–13 中午好、13–18 下午好、18–23 晚上好、其余 夜深了。

**分页 20 条一屏；标题截断 100 字符、预览截断 300 字符；提示停留 2s；自动保存去抖 ~1s。**

**Markdown 能力集**：代码高亮（可选行号）、任务列表（勾选 + 完成删除线）、表格、图片点击预览、音视频标签、大纲 TOC、公式与图表（mermaid 系）、首行缩进。**所有资源本地内置**，不许运行期取 CDN——这是"可达"的一部分，断网也要能读自己的日记。

**语言**：首发 en + zh-CN。参考项目 12 种（含 ar-EG RTL），RTL 支持推后有语言先加。

## 8. 顺序

1. **M0**：数据目录、条目增删改查、详情即编辑、去抖保存、软删除。跑起来能记能看能删。
2. **M1**：首页（周条 + 今天卡片 + 当日叠放）、迷你月历（桌面）、搜索框 + 结果高亮跳转、标签、修仙模式（日界与只读过去）。到这一步已经是可用的日记 App，可以发。
3. **M2**：导出人可读目录 / 备份恢复、心情记录、桌面三栏完善、应用锁、图片预览缩放、今天卡片的粘贴/拖入图片、移动端文件选择与分享接收（Android 系统分享已接，桌面分享入口未做）。心情只记录、不参与筛选；筛选条只保留标签。
4. **M3 及以后**：站内引用与反向链接、附件画廊、模板、"看源码"态，以及"高级搜索"（心情多选含"无心情"、起止日期、多关键词、正则）。全局快捷键与应用内快捷键不在计划内。

发版判据（M1 结束）：**能记、能找、能带走。** 这三件事都在，其他都是打磨。
